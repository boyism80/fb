# 봇 시나리오 테스트 계획

## 1. 목표

모든 직업이 다음을 사람처럼 해내는 것.

- 레벨에 맞는 사냥터를 솔로·그룹에 따라 골라서 찾아간다.
- 사냥이 어색하지 않다. 맞으면 반응하고, 스킬을 쓰고, 멍하니 서 있지 않는다.
- 최대한 죽지 않고, 죽으면 빨리 복구한다(부활 → 회복 → 시체 회수 → 복귀).
- 적절한 스킬을 배우고, 스킬 보유 여부에 따라 더 알맞은 사냥터로 옮긴다.
- 최종적으로 4차 승급(검성·태성 등)까지 가서 흉노족에서 그룹사냥을 한다.

흉노족 2층부터 흉노평민(체력 200만, 데미지 6.7만, 선공), 흉노전사(300만 / 7.2만), 흉노무사(300만 / 11만)가 나온다. 4차 승급 파티 + 도사 회복이 전제다.

### 합격 기준

- 시나리오 스위트 전체 통과(통과율 기준이 있는 시나리오는 그 기준 이상).
- 규칙 문서 2장의 비정상 현상이 시나리오 전체에서 0건.
- 그 뒤에 규모 테스트(수백 → 2,000봇)로 확인한다.

## 2. 원칙 (지난 실패에서 얻은 것)

1. **판단과 실행을 나눈다.** 판단은 "상태를 넣으면 의도가 나오는" 형태로 만든다. 판단 중간에 네트워크 대기나 이동을 섞지 않는다.
2. **판단끼리 엮지 않는다.** 보급, 사냥터, 전투, 그룹은 각자 독립된 규칙으로 판단한다. 하나의 점수로 모든 것을 환산하지 않는다.
3. **성향과 시드는 테스트 입력이다.** 테스트가 성향을 지정하고 난수 시드를 고정한다. 같은 입력이면 같은 판단이 나와야 한다.
4. **정답 하나가 아니라 합격 조건으로 검사한다.** 서버 쪽 랜덤(명중, 드롭, 몹 위치)은 "N초 안에 ~한다", "~가 한 번도 없다", "후보 목록 안에 있다" 같은 조건으로 본다. 확률적인 것은 여러 번 돌려 통과율로 본다.
5. **변경할 때마다 시나리오 전체를 다시 돌린다.** 사이드 이펙트는 이 단계에서 잡는다.
6. **격리된 공간에서 돌린다.** 인스턴스 맵 슬롯으로 시나리오끼리 서로 보이지 않게 한다.
7. **상황은 직접 만든다.** 몹 소환, NPC 배치, 스탯·장비·스킬·돈 설정, 가상 벽·가상 인원으로 재현하고 기다리지 않는다.

## 3. 구조

```
brain (판단)  ──의도──▶  실행(이동·전투·대화·거래)  ──▶  세계 어댑터  ──▶  game_bot / 서버
     ▲                                                        │
     └──────────────── 관찰(상태 스냅샷) ◀──────────────────────┘
```

- **세계 어댑터**: brain이 보는 세계와 실행 결과가 지나가는 층이다. 테스트는 여기에 가상 요소를 끼운다.
  - 시야: 가상 캐릭터를 시야 목록에 섞는다.
  - 지형: 가상 벽 칸을 통행 불가로 만든다.
  - 이동 결과: 가상 벽·가상 캐릭터 칸으로 가는 이동은 패킷을 보내지 않고 "막힘"으로 돌려준다.
  - 가상 요소는 수동적인 것만 다룬다(벽, 자리 차지, 인원). 응답이 필요한 상대(그룹원, 거래 상대)는 실제 봇으로 둔다.
- **판단 추적**: brain은 모든 결정을 구조화된 이벤트로 남긴다. 무엇을, 왜, 어떤 후보 중에서 골랐는지가 들어간다. 테스트는 이 기록을 조회해서 검사한다.

### 3.1 상태 구성 (계층형)

사람의 플레이 흐름(정비 → 이동 → 사냥 → 귀환 → 정비)을 뼈대로 한다. 상태끼리 점수로 경쟁하지 않고, 전환은 조건으로 정한다.

방식은 혼합형이다.

| 층 | 방식 | 이유 |
|---|---|---|
| 1층 반사 | behavior tree의 최상위 우선순위 가지 | 어느 상태든 매 틱 가장 먼저 확인해야 하는 순간 반응 |
| 2층 생활 주기 | 계층형 상태 머신(HFSM) | 단계가 분명한 긴 흐름. 현재 단계가 명시적이라 테스트(`brain:state`)와 파티 맞추기가 쉽다 |
| 3층 파티 | 맥락 값(역할) | 상태도 트리도 아니다. 1·2·4층이 함께 참고한다 |
| 4층 상태 안 판단 | 상태마다 behavior tree | 우선순위가 순간순간 바뀌는 세부 행동 |

- 생활 주기 전체를 behavior tree로 만들지 않는다. 매 틱 전체를 다시 평가하면 이전 brain처럼 볼일과 사냥 사이를 오가는 진동과 CPU 부담이 생긴다.
- 세부 반응을 상태로 만들지 않는다. "맞는 중", "회복 중", "추격 중" 같은 상태와 전환이 끝없이 늘어난다.
- 상태 머신은 진입할 때 그 상태의 트리를 만들고, 매 틱 트리를 한 번 실행한다. 트리가 "상태 종료 조건 충족"을 돌려주면 상태 머신이 전환 조건을 확인해 다음 상태로 간다.
- 트리 노드는 같은 형태를 쓴다: 우선순위 선택(selector), 순서 실행(sequence), 조건, 행동. 행동 노드는 진행 중·성공·실패를 돌려준다.
- 상태 안 트리의 예(`HUNT`): 줍기 → 버프 유지 → 공격 주문 → 평타 → 다음 몹 탐색 → 층 이동

**1층: 반사**

상태가 아니다. 어느 상태에서든 가장 먼저 동작하고, 코드 한 곳이 처리한다.

- 맞고 있으면: 이길 수 있으면 반격, 아니면 회복이나 이탈
- 위험 체력·마력: 회복 주문, 물약, 공력증강
- 반사가 동작하는 동안 상태는 멈추고, 반사가 끝나면 이어서 진행한다.

**2층: 생활 주기**

| 상태 | 하는 일 | 다음 상태로 가는 조건 |
|---|---|---|
| `DEAD` | 부활 → 회복(성황당 "감사합니다" 포함) → 시체 회수 | 살아 있고 회수가 끝나면 `PREPARE` |
| `PREPARE` | 마을 정비를 정해진 순서로 처리한다: 판매 → 예치·출금 → 보급 → 수리·장비 → 스킬 습득. 그룹이면 파티 정비를 맞춘다. | 준비 체크리스트 통과 시 `TRAVEL`, 진행 조건 충족 시 `PROGRESS` |
| `TRAVEL` | 사냥터 입구까지 이동한다. 그룹이면 집결 지점까지 간다. | 도착하면 `HUNT`(그룹이면 집결 완료 후) |
| `HUNT` | 사냥터에서 사냥하고 층을 이어 간다. | 보급 부족, 가방 가득, 위험 누적, 한 바퀴 끝이면 `RETURN` |
| `RETURN` | 가장 가까운 정비 가능 마을로 돌아간다. | 마을에 도착하면 `PREPARE` |
| `PROGRESS` | 정해진 진행 과제를 순서대로 처리한다: 튜토리얼(낙랑 소개 퀘스트, 낙랑의두루마리 1~5), 직업 선택, 승급(1~4차), 꼭 필요한 퀘스트. 과제 안에서 이동·사냥이 필요하면 `TRAVEL`·`HUNT`를 그 과제의 목적지·조건으로 빌려 쓴다. | 과제를 마치면 `PREPARE` |

- 사망은 어느 상태에서든 `DEAD`로 바로 넘어간다.
- 새 캐릭터의 첫 상태는 `PROGRESS`이고 과제는 튜토리얼이다. 튜토리얼을 따로 상태로 두지 않는 이유는, 튜토리얼도 직업 선택·승급과 같은 "정해진 과제 연쇄"이고 그 안의 이동·사냥은 일반 `TRAVEL`·`HUNT`와 같기 때문이다. 과제를 하나의 방식으로 다루면 튜토리얼과 승급이 같은 코드와 같은 시나리오 틀을 쓴다.
- 준비 체크리스트는 규칙 문서 1.8~1.11(보급, 돈, 장비, 스킬)을 그대로 항목으로 옮긴다. 예: 마법 직업은 마력 물약 N회분 이상, 이탈 수단 1개 이상, 장비 내구도 기준 이상.

**3층: 파티**

상태가 아니라 맥락이다. 역할은 솔로, 리더, 구성원(격수·도사)이다. 같은 상태 안에서 역할에 따라 세부 행동만 바뀐다.

| 상태 | 솔로 | 리더 | 구성원 |
|---|---|---|---|
| `PREPARE` | 혼자 정비 | 구성원 정비가 끝나기를 기다리고, 사냥터를 정한다 | 정비 후 리더에게 준비 완료를 알린다 |
| `TRAVEL` | 입구까지 이동 | 입구에서 모두 모일 때까지 대기, 시간 안에 안 오면 사유를 남기고 내보낸다 | 리더의 현재 위치가 아니라 입구로 간다. 먼저 안에 있으면 안에서 기다린다. |
| `HUNT` | 혼자 사냥 | 앞장서서 층 진행 | 격수는 공격, 도사는 회복과 따라가기 |
| `RETURN` | 혼자 복귀 | 파티 전체 복귀를 정한다 | 리더 결정을 따른다(전투 불능이면 먼저 복귀를 요청) |

그룹 결성·해산은 `PREPARE`에서 다룬다. 해산 사유(리더 이탈, 전투 불능, 사망, 고가치 스킬 습득 등)는 항상 기록한다.

**4층: 상태 안의 세부 판단 (behavior tree)**

각 상태 안에서만 그 상태의 트리로 판단한다. 다른 상태의 판단과 점수를 공유하지 않는다.

- `PREPARE`: 무엇을 얼마나 살지, 어떤 스킬을 먼저 배울지
- `TRAVEL`: 경로, 이동 마법 사용, 막힘 대응
- `HUNT`: 어느 몹을 칠지, 어떤 스킬을 쓸지, 무엇을 주울지
- 사냥터 선택: `PREPARE`가 끝날 때 한 번 정한다(사냥터 표 + 위험·혼잡 확인).

**처음에는 넣지 않는 것**

목적 없는 배회, 봇 간 거래, 일반 퀘스트. 기본 흐름이 안정된 뒤 추가한다.

## 4. 필요한 빌트인

책임을 객체별로 나눈다. bot에는 brain을 붙이고 떼는 함수 하나만 추가한다.

```lua
local bot   = ctx:bot(1)
local brain = brain.new({ persona = { hunt = 1.0, money = 0.5 }, seed = 42 })
local world = world.new(ctx:slot())
local stage = stage.new(ctx)

stage:level(bot, 40)
stage:class(bot, "전사", 0)
bot:brain(brain)                 -- attach
world:block(bot:map(), 10, 5, 1, 3)
expect.within(30, function() return brain:state(bot).name == "HUNT" end)
bot:brain(nil)                   -- detach
```

### 4.1 bot (기존 객체에 하나만 추가)

| 함수 | 설명 |
|---|---|
| `bot:brain(brain)` | brain을 붙인다. `nil`이면 뗀다. 떼면 봇은 아무것도 하지 않는다. |

### 4.2 brain (신규 객체)

생성과 제어

| 함수 | 설명 |
|---|---|
| `brain.new(opts)` | brain을 만든다. `opts.persona`(성향), `opts.seed`(난수 시드) |
| `brain:pause(bot)` / `brain:resume(bot)` | 판단을 멈추거나 다시 돌린다. 상황을 세팅하는 동안 쓴다. |
| `brain:step(bot)` | 판단을 한 번만 돌리고 의도를 돌려준다. 실행은 하지 않는다. |
| `brain:persona(bot, table)` | 실행 중에 성향 일부를 바꾼다. |

관찰

| 함수 | 반환 |
|---|---|
| `brain:state(bot)` | 현재 상태(`DEAD`·`PREPARE`·`TRAVEL`·`HUNT`·`RETURN`·`PROGRESS`), 역할(솔로·리더·구성원), 시작 시각, 반사 동작 중 여부 |
| `brain:progress(bot)` | `PROGRESS`의 현재 과제(튜토리얼·직업 선택·승급·퀘스트)와 과제 안 단계, 남은 과제 목록 |
| `brain:states(bot, since)` | 그 시각 이후의 상태 전환 기록(전환 조건 포함) |
| `brain:checklist(bot)` | `PREPARE` 준비 체크리스트의 항목별 통과 여부 |
| `brain:intent(bot)` | 다음 행동 의도(이동 목적지, 공격 대상, 시전 주문, 구매 품목 등) |
| `brain:tree(bot)` | 현재 상태 트리에서 마지막 틱에 실행된 노드 경로와 각 노드 결과(진행 중·성공·실패) |
| `brain:ground(bot)` | 고른 사냥터, 후보 목록, 각 후보의 탈락·선택 이유 |
| `brain:lap(bot)` | 한 바퀴 계획(층 목록, 현재 층) |
| `brain:route(bot, map, x, y)` | 그 목적지까지의 계획 경로(맵·워프·이동 마법) |
| `brain:party(bot)` | 그룹 상태(역할, 리더, 구성원, 집결 지점, 대기 여부, 내보낸 구성원과 이유) |
| `brain:supply(bot)` | 보급 판단(필요량, 보유량, 다음 구매, 출금·판매 계획) |
| `brain:lessons(bot)` | 배울 스킬 후보, 순위, 보류 이유(돈·재료·레벨) |
| `brain:events(bot, since, kind)` | 판단 추적 이벤트 |
| `brain:anomalies(bot, since)` | 비정상 현상 기록(맞는 동안 무반응, 맨손 강몹 공격, 스킬 미사용, 상태 헛돌기 등) |
| `brain:metrics(bot)` | 처치 수, 사망 수, 분당 경험치, 전투 시간 비율, 무반응 누적 시간, 판단 1회 평균 CPU 시간 |

### 4.3 world (신규 객체, 테스트 전용)

brain이 보는 세계와 이동 결과에 끼우는 가상 요소다. 슬롯(인스턴스) 단위로 만들고, 그 슬롯에서 brain을 가진 봇에게만 적용된다.

| 함수 | 설명 |
|---|---|
| `world.new(slot)` | 그 인스턴스 슬롯용 가상 세계를 만든다. |
| `world:block(map, x, y, w, h)` / `world:unblock(...)` | 가상 벽을 세우거나 지운다. |
| `world:phantom(map, x, y, opts)` | 가상 캐릭터(이름·직업·레벨). 칸을 차지하고 시야와 인원 집계에 잡힌다. 돌려받은 핸들로 이동·삭제한다. |
| `world:crowd(map, count)` | 그 맵에 가상 인원 N명이 있는 것으로 집계한다(혼잡 판단용). |
| `world:fail(action, count, reason)` | 다음 N회 행동을 실패시킨다. 예: 주문 시간초과, 워프 거부, 경로 없음, 구매 실패. |
| `world:clear()` | 가상 요소를 모두 지운다. |

### 4.4 stage (신규 객체, 상황 세팅)

새 세팅 함수는 bot에 붙이지 않고 stage에 둔다. 이미 bot에 있는 세팅 빌트인(`setup_bot_stats`, `set_current_hp_mp`, `change_class`, `learn_spell(s)`, `create_item`, `equip`, `spawn_monster(s)`, `create_npc`, `map_move`, `invite_group` 등)은 그대로 쓴다.

| 함수 | 설명 |
|---|---|
| `stage.new(ctx)` | 그 시나리오의 슬롯과 봇들을 대상으로 만든다. |
| `stage:level(bot, n)` / `stage:exp(bot, n)` | 레벨과 경험치를 직접 지정한다. |
| `stage:class(bot, name, promotion)` | 직업과 승급 단계(0~4)를 지정한다. |
| `stage:money(bot, n)` / `stage:deposit(bot, n)` | 소지금과 주막 예치금을 지정한다. |
| `stage:durability(bot, item, percent)` | 장비 내구도를 지정한다. |
| `stage:kill(bot)` | 즉시 사망 상태로 만든다(부활 흐름 테스트용). |
| `stage:monster(map, x, y, opts)` | 체력·공격 여부·이동 여부를 고정한 몹을 소환한다(랜덤 줄이기). |
| `stage:obstacle(map, x, y)` | 통행을 막는 실제 장애물(NPC 등)을 놓는다(가능 여부 확인 필요). |

### 4.5 검사 헬퍼 (Lua lib, 신규)

| 함수 | 설명 |
|---|---|
| `expect.within(seconds, fn, message)` | 시간 안에 조건이 참이 되어야 한다. |
| `expect.never(seconds, fn, message)` | 그 시간 동안 조건이 한 번도 참이면 안 된다. |
| `expect.always(seconds, fn, message)` | 그 시간 동안 조건이 계속 참이어야 한다. |
| `expect.one_of(value, list, message)` | 값이 허용 목록 안에 있어야 한다. |
| `expect.rate(runs, pass, fn)` | 시드를 바꿔 runs번 돌려 pass번 이상 통과해야 한다. |
| `expect.no_anomaly(brain, bot, since)` | 비정상 현상 기록이 0건이어야 한다. |

## 5. 실행 방식

- 스위트 하나로 돌린다: `brain_scenario_test`, 라벨 `scenario`.
- 시나리오 파일은 `scripts/integration/scenarios/brain/<분류>/<이름>.lua`에 둔다.
- 각 시나리오는 인스턴스 슬롯 하나와 봇 몇 개를 받아서 병렬 레인으로 돈다.
- 시나리오마다 성향과 시드를 고정한다. 통과율 시나리오는 시드 목록을 돈다.
- 결과에는 시나리오별로 통과·실패, 실패한 조건, 마지막 판단 추적 이벤트 몇 개를 남긴다.
- 브랜치에서 brain을 바꿀 때마다 스위트 전체를 돌린다.

## 6. 시나리오 목록

`[결정]`은 `brain:step`이나 관찰 함수만으로 확인하는 판단 테스트다. `[행동]`은 실제로 움직이고 싸우는 테스트다. `[확률]`은 시드를 바꿔 통과율로 보는 테스트다.

## 8. 시나리오 추가 규칙

- 규모 테스트에서 새 문제가 나오면 먼저 재현 시나리오를 만들고 실패하는 것을 확인한다. 그다음에 고친다.
- 시나리오 하나는 규칙 문서의 한 문장(또는 비정상 현상 한 항목)에 대응시킨다.
- 시나리오가 실패하면 판단 추적 이벤트로 원인을 확인한다. 조건을 느슨하게 바꿔서 통과시키지 않는다.

## 9. 확인이 필요한 것

- 사냥터에서도 인스턴스 슬롯 이동(`/맵이동 맵 x y 슬롯`)이 되는지, 슬롯별로 몹 스폰이 따로 도는지
- `create_npc`로 만든 NPC가 실제로 통행을 막는지
- 승급(1~4차) 조건과 진행 방법(퀘스트·NPC·재료)
- 레벨·승급·예치금 직접 지정용 개발 명령이 있는지, 없으면 서버에 추가할지
- 사냥터 허용 표(E1)를 누가 어떤 기준으로 만들지: 서버 데이터로 초안을 만들고 직접 검토하는 방식을 제안
